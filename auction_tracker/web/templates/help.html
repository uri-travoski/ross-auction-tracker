Ross Auction IT Tracker — Guide & Documentation

A comprehensive reference for deploying on your homeserver, configuring custom AI providers with fallbacks, migrating historical data, and using every feature of the tracker.

Quick Jump: 🚀 Standalone Setup ⚙️ Configuration & Secrets 🤖 AI Providers & Fallbacks 📦 Data Persistence & Migration 🖥️ How to Use the Web App 📊 The 2 "Changes Observed" Tables 🛠️ CLI & Docker Commands
1. Quickstart & Homeserver Setup (Docker Compose)

The tracker runs as a standalone, self-contained container with SQLite, Playwright headless Chromium, background scheduler, and web server pre-packaged. You do not need Python installed on your server.

Step 1
Create a directory and download docker-compose.yml: 
mkdir -p ~/ross-auction-tracker && cd ~/ross-auction-tracker
curl -O https://raw.githubusercontent.com/uri-travoski/ross-auction-tracker/main/docker-compose.yml
Step 2
Create the persistent data directory: 
mkdir -p data
All database files, downloaded high-resolution images, reports, and logs live inside this ./data directory on the host. Upgrading or restarting the container preserves all data.
Step 3
(Optional) Create your .env file for SMTP alerts & AI keys: 
curl -O https://raw.githubusercontent.com/uri-travoski/ross-auction-tracker/main/.env.example
cp .env.example .env
nano .env
If you omit .env, the app starts with safe defaults: log-only notifications and deterministic keyword filtering.
Step 4
Launch the container: 
docker compose up -d

Open your browser and navigate to http://<your-server-ip>:8080.

2. Configuration Architecture (.env vs config.yaml)

Configuration follows strict layering: later sources override earlier ones:

1
Built-in Defaults
2
config.yaml / data/config.yaml
3
.env (Secrets)
4
Real Environment Variables

Where do settings belong?

Setting Type Where to Put It Examples
Secrets & Credentials .env SMTP passwords, API keys (GROQ_API_KEY, DEEPSEEK_API_KEY, OPENAI_API_KEY)
Behavioural Settings config.yaml or ./data/config.yaml Scan intervals, IT keywords, AI model selection, fallback chains, timeouts
Docker Overrides environment: in docker-compose AT__SCHEDULE__CHANGE_EVERY_HOURS=3, WEB_PORT=8080

3. AI Providers & Automatic Fallback Pipelines

The tracker supports any OpenAI-compatible (/chat/completions) or Anthropic-compatible (/messages) API endpoint. You can configure multiple providers and arrange them in fallback order per task.

How Fallbacks Work: When a task runs, the tracker contacts Provider #1. If Provider #1 fails (rate limit, timeout, or network issue), the tracker immediately and automatically executes Provider #2, then Provider #3. If all fail, fail_open: true ensures deterministic keyword scans continue without interrupting your auctions.

Every Performable AI Task:

Task Identifier What It Does Recommended Primary Recommended Fallbacks
classify Evaluates auction titles and lot lists to filter genuine IT equipment and reject non-IT items (e.g. diesel engines, chemicals, gym racks). Groq (fastest) openai → deepseek → openrouter → anthropic → local-ollama
extract_specs Parses lot descriptions into structured attributes: CPU, RAM, SSD, form factor, brand, model, and condition. Groq openai → deepseek → openrouter → anthropic
summarize_scan Generates a human-readable summary of each scan: new lots found, bid jumps, and closing auctions. Groq openai → deepseek → openrouter → anthropic
estimate_price Calculates fair market valuation and recommended maximum bid by comparing against past sales. DeepSeek (reasoning) openai-reasoning (GPT-4o) → anthropic (Claude 3.5) → openrouter
ask Powers the free-form operator Q&A tab (/ask) to answer questions about models, prices, and trends. DeepSeek openai-reasoning → anthropic → openrouter

Configuring in config.yaml (or ./data/config.yaml):

ai:
  enabled: true
  fail_open: true             # Never crash scans if AI is unreachable
  cache_enabled: true         # Avoids paying for the same query twice
  cache_ttl_days: 30

  providers:
    - name: "groq"
      kind: "openai"
      base_url: "https://api.groq.com/openai/v1"
      model: "llama-3.3-70b-versatile"
      api_key_env: "GROQ_API_KEY"
      enabled: true

    - name: "deepseek"
      kind: "openai"
      base_url: "https://api.deepseek.com/v1"
      model: "deepseek-chat"
      api_key_env: "DEEPSEEK_API_KEY"
      enabled: true

    - name: "openai"
      kind: "openai"
      base_url: "https://api.openai.com/v1"
      model: "gpt-4o-mini"
      api_key_env: "OPENAI_API_KEY"
      enabled: true

    - name: "openai-reasoning"
      kind: "openai"
      base_url: "https://api.openai.com/v1"
      model: "gpt-4o"
      api_key_env: "OPENAI_API_KEY"
      enabled: true

    - name: "anthropic"
      kind: "anthropic"
      base_url: "https://api.anthropic.com/v1"
      model: "claude-3-5-sonnet-20241022"
      api_key_env: "ANTHROPIC_API_KEY"
      enabled: true

    - name: "local-ollama"
      kind: "openai"
      base_url: "http://host.docker.internal:11434/v1"
      model: "llama3.1:8b"
      require_api_key: false
      enabled: false

  tasks:
    classify:
      providers: ["groq", "openai", "deepseek", "anthropic"]
    extract_specs:
      providers: ["groq", "openai", "deepseek", "anthropic"]
    summarize_scan:
      providers: ["groq", "openai", "deepseek", "anthropic"]
    estimate_price:
      providers: ["deepseek", "openai-reasoning", "anthropic", "groq"]
    ask:
      providers: ["deepseek", "openai-reasoning", "anthropic", "groq"]
4. Data Persistence & Migrating to a Homeserver

All data is isolated in the host directory ./data/ mounted into the container at /app/data.

data/auctions.db The primary SQLite database (WAL mode). Contains all past & current auctions, lots, descriptions, prices, bid histories, and changes.
data/images/ All downloaded lot thumbnail and high-resolution original photos (deduplicated by SHA-256).
data/reports/ Exported standalone HTML reports.
data/logs/ Daily scan and system diagnostic logs.

How to migrate data to your homeserver:

To carry over all past auctions, prices, and lots to a new installation:

Option A
Direct copy over SSH (Fastest): 
# Copy database and images to homeserver:
rsync -avz ./data/ user@homeserver:/path/to/ross-auction-tracker/data/

# Or copy just the SQLite database file:
scp ./data/auctions.db* user@homeserver:/path/to/ross-auction-tracker/data/
Option B
Using the built-in archive snapshot: 
# 1. Create a zip archive:
docker compose --profile archive run --rm archive

# 2. Copy data/auction-tracker-archive.zip to your homeserver and unzip into ./data/
5. How to Use Every Feature in the Web Application

📊 Dashboard & Auction Cards

The dashboard displays Current IT auctions and Past IT auctions in a card grid (3–5 cards per row).

  • Highlighted Current Auctions: Highlighted with a vivid blue border, live pulsing indicator, closing date, and real-time countdown (e.g. 5 days 17 hrs).
  • Content Highlights: Lot count, total bid count, and current total value at a glance.
  • Quick Navigation: Direct View Lots button for the local catalogue and Auction site ↗ to jump to Ross's.

🔄 Manual Scan & IT Recheck

On the Current auctions page, two dedicated controls allow on-demand administration:

  • "Check current auctions" button: Instantly discovers online auctions from Ross's site and scans for new bids without waiting for the scheduled cron. Safe and deduplicated.
  • "Recheck IT status" button: Re-evaluates all saved auctions against the negative keyword filters and AI classifier to eliminate any false positives.

📦 Auction Catalogue & Lots

Each auction page provides the complete catalogued inventory with smart filtering:

  • Filter by search term, with bids, without bids, or changed lots.
  • Bid Deltas: Real-time price movement indicators showing previous bids and bid jumps (e.g. +$40, was $120).
  • Link to Auction: Direct button to open the real auction on auctions.com.au.

🖼️ Local Lot Details & Images

Clicking any lot description or image opens its local details page (/lot/<id>):

  • Offline Media: High-resolution photos and thumbnails downloaded directly to your server. Viewing does not contact external tracking servers.
  • Specs: Extracted CPU, RAM, storage, form factor, and condition badges.
  • Reserve Met: Indicators indicating whether the lot reserve price has been met.

⚖️ Side-by-Side Comparison (/compare)

Select up to 4 lots across different auctions to compare specifications, photos, and current/final prices side-by-side to make informed bidding decisions.

💡 Ask the AI (/ask)

Ask natural-language questions like "What should I pay for an HP EliteDesk G6 Mini with 16GB RAM?".

  • The AI checks against historical winning bids in your SQLite database.
  • Provides a fair price range, maximum recommended bid, confidence rating, and potential caveats.
6. Understanding the Two Types of "Changes Observed" Tables

Ross Auction Tracker tracks every mutation to listings, prices, and terms. Changes are recorded at two distinct levels:

Type 1: Overall Auction Changes Observed

Location: Located at the very bottom of the Auction Details page (/auction/<id>), placed after the listed lots catalogue.

Captures the lifecycle of the entire auction from start to finish:

  • Lots added or withdrawn from the auction catalogue.
  • Auction closing time extensions (anti-sniping extensions).
  • Terms, pickup dates, and inspection description edits.
  • All significant lot price jumps summarized chronologically.
  • Direct clickable links to local lot detail pages for each event.

Type 2: Per-Lot Changes Observed

Location: Located on each individual item page (/lot/<id>).

Captures the micro-history of that specific piece of hardware:

  • Every individual bid increase, previous bid value, and new bid value.
  • Increases in total bid count and unique competing bidders.
  • Transitions when the reserve price is reached.
  • Edits made by the auctioneer to the title, lot description, or specs.
  • Photo gallery updates or added photos.
